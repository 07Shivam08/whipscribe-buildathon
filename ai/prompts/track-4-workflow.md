# Starter prompt — Track 4, invent a workflow

Paste this as the first message to Claude, Codex, Gemini, Cursor or any other tool.

---

Read AGENTS.md in this repository first and follow it.

I am doing Track 4 of the WhipScribe Buildathon: a workflow that takes one
specific kind of person from a recording to the thing they actually wanted,
using the WhipScribe API (https://whipscribe.com/docs) and/or the WhipScribe
MCP server (https://whipscribe.com/claude).

The person: <fill in — e.g. a medical student revising from six hours of lectures a week>
What they do today: <fill in>
What it costs them: <fill in — hours, mistakes, things forgotten>
The result they want: <fill in — e.g. study cards and a weekly quiz>
Where the result should land: <fill in — a tool they already use, a file, a chat>
My stack: <fill in>

Work with me one step at a time, stopping for my confirmation between steps:

1. Help me write the one-page problem statement in `apps/<my-name>/README.md`.
   Push back if the person or the cost is vague.
2. Draw the workflow as numbered steps. For each step say: what the person
   does, what the API or MCP does, what they see. Mark the steps we remove
   from their day.
3. Make one real request to the API with my own recording and show me the
   actual response before we build on it. Do not assume any field the docs
   or the response do not show.
4. Build the shortest path end to end: recording in, result where it should
   land. No settings screens, no accounts, no dashboard.
5. Design the states: no recording yet, a long one, one that fails, the
   result already delivered.
6. Help me plan a two-minute recording of it working, and write the vision
   section: who else this serves, what it would need, what I would build next.

Rules: my own account and recordings only; no key or token in a tracked
file; do not invent API behaviour; small commits with messages that name the
change.

Start with step 1 and ask me anything you need before we write.
