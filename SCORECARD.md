# Scorecard — 100 points

Tick what is true of your entry. Copy this list into your **Introduction**
issue or your pull request; the boxes stay tickable there and we score from
them. (The same list, with a live total, is at
[neugence.github.io/whipscribe-buildathon/scorecard.html](https://neugence.github.io/whipscribe-buildathon/scorecard.html).)

### UI and UX craft — 30

- [ ] Every screen has designed empty, loading, error and done states — **6**
- [ ] Works on a phone-sized screen, or has a clear reason not to — **6**
- [ ] Keyboard reachable, readable contrast, labelled controls — **5**
- [ ] Copy is in the user's words, not the system's — **5**
- [ ] The first run is designed: what a new user sees before any data — **4**
- [ ] Before/after screenshots or a short recording attached — **4**

### Shipped apps — 20

- [ ] At least one app of mine is live in the App Store or Play Store today — **6**
- [ ] It has real users and reviews, and I have answered some — **4**
- [ ] I shipped an update that fixed a crash or a review complaint — **4**
- [ ] I handled store review, signing and release myself — **3**
- [ ] I can say what I would do differently next time — **3**

### Building with AI, well — 20

- [ ] The README explains the decisions, not just the features — **6**
- [ ] Commits are small and named for the change — **5**
- [ ] I removed or rewrote something the tool produced, and say what and why — **5**
- [ ] No invented API behaviour: every call matches the docs or a real response — **4**

### Finishing — 20

- [ ] One full flow works end to end from a clean install — **8**
- [ ] Someone other than me used it and I changed something because of it — **5**
- [ ] The README says exactly what does not work yet — **4**
- [ ] Install and run instructions work on a machine that is not mine — **3**

### Learning in the open — 10

- [ ] I name something that was new to me and how I learned it — **4**
- [ ] I describe a thing that went wrong and how I found and fixed it — **3**
- [ ] I asked a question in an issue early instead of guessing late — **3**

**My total:** ___ / 100

**Reading it:** 80 and above is a contender for the top two. 65–79 is strong;
say what you would do with two more weeks. Below 50, keep going and resubmit —
small, early pull requests get feedback.

Track 1 entries (bug reports and proposals) are scored on UI and UX craft,
finishing (is the fix small, correct and complete?) and learning; shipped apps
and AI use count where you show them.
